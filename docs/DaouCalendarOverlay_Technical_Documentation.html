이 프로젝트의 중요한 설계 포인트는 별도의 native-host EXE를 만들지 않고 같은 EXE를 재사용한다는 점이다.

B. Native Host 모드

  1. Chrome이 같은 EXE를 Native Messaging host로 실행
  2. Program.Main이 인자에 고정 extension origin이 있는지 판정
  3. WPF Application/App.xaml 리소스를 만들지 않음
  4. LogService.Initialize(..., "host")로 host 로그 초기화

T2.1부터 진입점은 WPF가 자동 생성하던 Main이 아니라 Program.Main이다(csproj의 StartupObject, EnableDefaultApplicationDefinition=false). App 참조는 RunGui에 격리돼 host 모드에서는 App 인스턴스가 만들어지지 않는다. native 모드에서 App 필드 초기화(SettingsService/CacheService 생성자)로 LocalAppData 디렉터리가 만들어지던 동작은 T2.1 이후 사라졌다. host 모드가 만드는 폴더는 LogService.Initialize가 여는 로그 폴더뿐이다.

using System.Runtime.CompilerServices;
using DaouCalendarOverlay.Services;

namespace DaouCalendarOverlay;

internal static class Program
{
    [STAThread]
    internal static int Main(string[] args)
    {
        // T2.4: --uninstall 등 인자 처리는 여기(native 분기 이전)에 추가한다.
        if (StartupModeParser.IsNativeInvocation(args))
            return RunNativeHost();

        return RunGui();
    }

    // App 타입 참조를 별도 메서드로 격리한다. Main 본문이 App을 직접 참조하면 Main을 JIT할 때
    // WPF 어셈블리(PresentationFramework/WindowsBase/System.Xaml)가 host 모드에서도 로드된다.
    [MethodImpl(MethodImplOptions.NoInlining)]
    private static int RunGui()
    {
        var app = new App();
        app.InitializeComponent();
        return app.Run();
    }

    private static int RunNativeHost()
    {
        // host 분기는 App.OnStartup을 타지 않으므로 여기서 반드시 로깅을 초기화한다.
        LogService.Initialize(LogService.DefaultLogDirectory, "host");
        LogService.Info("host", $"host 모드 시작 pid={Environment.ProcessId}");
        try
        {
            NativeMessagingHost.RunAsync().GetAwaiter().GetResult();
            return 0;
        }
        catch (Exception ex)
        {
            LogService.Error("host", "native host 실행 실패", ex);
            return 1;
        }
    }
}

6.2 왜 고정 Extension ID인가

manifest.json에 공개키 key를 포함해 unpacked extension도 동일 ID를 갖도록 만든다. Native Messaging host manifest의 allowed_origins는 정확한 extension origin을 요구하므로 ID가 매번 바뀌면 연결이 깨진다.

6.3 세션 쿠키 수집 방식

readCookiesFromAllStores는 해당 Daou URL의 쿠키를 한 store에서만 가져온다. 먼저 기본 store(DEFAULT_COOKIE_STORE_ID = "0")를 chrome.cookies.getAll({ url, storeId: "0" })로 조회하고, 비었을 때만 storeId를 지정하지 않은 암시적 store를 조회한다. 그래도 비면 chrome.cookies.getAllCookieStores()를 순회하되(기본 store는 건너뜀) 쿠키가 나온 첫 store 하나의 결과만 사용한다. 여러 store의 쿠키를 한 Cookie 헤더로 합치지 않는다. 시크릿 창이나 다른 프로필의 세션 쿠키가 섞이면 인증이 깨지기 때문이다. 각 단계의 예외는 삼키고 다음 단계로 넘어간다. live cookie 조회가 모두 비면 기존과 같이 chrome.storage.session 캐시를 fallback으로 사용한다.

쿠키 캐시는 디스크 영구 저장용이 아니다. browser session 메모리 범위에서 유지해 service worker suspend/resume에는 살아 있고 완전한 Chrome 재시작 시에는 사라질 수 있게 했다.

7. Chrome Native Messaging + Windows Named Pipe

7.1 메시지 framing

Chrome Native Messaging은 stdin/stdout에 JSON을 그대로 쓰는 것이 아니라 4바이트 little-endian payload length + UTF-8 JSON 프레임을 사용한다. 동일 framing을 Named Pipe에도 재사용한다.

using System.Buffers.Binary;
using System.IO;
using System.IO.Pipes;
using System.Text;
using System.Text.Json.Serialization;

namespace DaouCalendarOverlay.Services;

public static class NativeBridgeProtocol
{
    public const string PipeName = "DaouCalendarOverlay.NativeBridge.v7";
    public const string HostName = "com.daou.calendar_overlay";
    public const string ExtensionId = "gkchgbpcbljkgabjcgjelacfkphcmhmi";
    public const string ExtensionOrigin = "chrome-extension://gkchgbpcbljkgabjcgjelacfkphcmhmi/";

    public static async Task<byte[]?> ReadFrameAsync(Stream stream, int maxBytes, CancellationToken cancellationToken)
    {
        var lengthBytes = new byte[4];
        if (!await ReadExactAsync(stream, lengthBytes, cancellationToken))
            return null;

        var length = BinaryPrimitives.ReadInt32LittleEndian(lengthBytes);
        if (length < 0 || length > maxBytes)
            throw new InvalidDataException($"Invalid native message length: {length}");

        var payload = new byte[length];
        if (length > 0 && !await ReadExactAsync(stream, payload, cancellationToken))
            throw new EndOfStreamException("Native message ended before the declared payload length.");

        return payload;
    }

    public static async Task WriteFrameAsync(Stream stream, ReadOnlyMemory<byte> payload, CancellationToken cancellationToken)
    {
        var lengthBytes = new byte[4];
        BinaryPrimitives.WriteInt32LittleEndian(lengthBytes, payload.Length);
        await stream.WriteAsync(lengthBytes, cancellationToken);
        if (!payload.IsEmpty)
            await stream.WriteAsync(payload, cancellationToken);
        await stream.FlushAsync(cancellationToken);
    }

    public static byte[] Utf8(string value) => Encoding.UTF8.GetBytes(value);

    private static async Task<bool> ReadExactAsync(Stream stream, Memory<byte> buffer, CancellationToken cancellationToken)
    {
        var offset = 0;
        while (offset < buffer.Length)
        {
            var read = await stream.ReadAsync(buffer[offset..], cancellationToken);
            if (read == 0)
                return false;
            offset += read;
        }

        return true;
    }
}

7.2 Native Host는 얇은 relay

Chrome이 실행하는 native host는 독립 프로세스다. 실제 UI 상태·설정·동기화 requestId는 이미 실행 중인 GUI 프로세스에 있으므로 host는 stdin 메시지를 Named Pipe로 넘기고 응답을 stdout으로 돌려주는 역할만 한다.

// Services/NativeMessagingHost.cs — Chrome stdio↔Named Pipe 중계
private const int ChromeInputLimit = 64 * 1024 * 1024;
private const int ChromeOutputLimit = 1024 * 1024;

public static async Task RunAsync(CancellationToken cancellationToken = default)
{
    using var input = Console.OpenStandardInput();
    using var output = Console.OpenStandardOutput();
    var sw = Stopwatch.StartNew();

    try
    {
        var request = await NativeBridgeProtocol.ReadFrameAsync(input, ChromeInputLimit, cancellationToken);
        if (request is null)
            return;

        LogService.Info("host", $"요청 수신 {BridgeLogSummary.DescribeRequest(request)}");

        var response = await NativeHostRelay.ConnectAndExchangeAsync(
            NativeBridgeProtocol.PipeName,
            request,
            Environment.ProcessPath,
            NativeHostRelay.DefaultConnectTimeoutMs,
            cancellationToken);

        if (response.Length > ChromeOutputLimit)
        {
            LogService.Warn("host", "응답이 Chrome 1MB 한도를 초과");
            response = SerializeError("Native host response exceeded Chrome's 1 MB limit.");
        }

        await NativeBridgeProtocol.WriteFrameAsync(output, response, cancellationToken);
        LogService.Info("host", $"요청 완료 elapsed={sw.ElapsedMilliseconds}ms");
    }
    catch (Exception ex)
    {
        LogService.Error("host", "native host 오류", ex);
        var response = SerializeError($"Native Messaging Host 오류: {ex.Message}");
        if (response.Length <= ChromeOutputLimit)
        {
            try { await NativeBridgeProtocol.WriteFrameAsync(output, response, cancellationToken); }
            catch (Exception writeEx) { LogService.Warn("host", "오류 응답 전송 실패", writeEx); }
        }
    }
}

// Services/NativeHostRelay.cs — 서버 신원을 확인한 뒤에만 프레임을 중계한다

public const int PipeMessageLimit = 8 * 1024 * 1024;
private const string LogCategory = "host.pipe";

public static async Task<byte[]> ConnectAndExchangeAsync(
    string pipeName,
    byte[] request,
    string? selfExecutablePath,
    int connectTimeoutMs,
    CancellationToken cancellationToken)
{
    try
    {
        using var pipe = new NamedPipeClientStream(
            ".",
            pipeName,
            PipeDirection.InOut,
            PipeOptions.Asynchronous | PipeOptions.CurrentUserOnly);

        await pipe.ConnectAsync(connectTimeoutMs, cancellationToken);

        var serverProcessId = PipePeerVerifier.TryGetServerProcessId(pipe.SafePipeHandle);
        if (serverProcessId is null)
        {
            LogService.Warn(LogCategory, "파이프 서버 PID를 확인할 수 없어 요청을 전송하지 않았습니다.");
            return SerializeError(PipePeerVerifier.BuildUnverifiablePeerError());
        }

        var serverPath = PipePeerVerifier.TryGetProcessPath((int)serverProcessId.Value);
        if (!PipePeerVerifier.IsSameExecutable(selfExecutablePath, serverPath))
        {
            LogService.Warn(
                LogCategory,
                $"신뢰할 수 없는 파이프 서버: pid={serverProcessId.Value}, server={serverPath ?? "(unknown)"}, self={selfExecutablePath ?? "(unknown)"}");
            return SerializeError(PipePeerVerifier.BuildUntrustedPeerError(serverProcessId.Value));
        }

        await NativeBridgeProtocol.WriteFrameAsync(pipe, request, cancellationToken);
        return await NativeBridgeProtocol.ReadFrameAsync(pipe, PipeMessageLimit, cancellationToken)
            ?? SerializeError("Overlay bridge closed without a response.");
    }
    catch (OperationCanceledException) when (cancellationToken.IsCancellationRequested)
    {
        // 취소는 상위(NativeMessagingHost.RunAsync)가 기존대로 처리한다.
        throw;
    }
    catch (UnauthorizedAccessException ex)
    {
        // CurrentUserOnly: 파이프 소유자가 현재 사용자가 아니다(예: 관리자 권한으로 실행된 오버레이).
        LogService.Warn(LogCategory, "파이프 서버가 현재 사용자 소유가 아닙니다: " + ex.Message);
        return SerializeError("Native Bridge 서버가 현재 사용자 소유가 아니어서 연결하지 않았습니다(오버레이를 관리자 권한으로 실행했는지 확인하세요).");
    }
    catch (Exception ex)
    {
        LogService.Warn(LogCategory, "파이프 연결 실패", ex);
        return SerializeError($"Daou Calendar Overlay가 실행 중이지 않거나 Native Bridge에 연결할 수 없습니다: {ex.Message}");
    }
}

클라이언트 쪽 파이프도 PipeOptions.CurrentUserOnly를 지정하므로 다른 Windows 계정이 만든 파이프에는 애초에 연결되지 않는다. 같은 계정이 파이프 이름을 선점한 경우를 대비해, 연결 직후 GetNamedPipeServerProcessId로 서버 PID를 얻고 그 프로세스의 실행 파일 경로를 Environment.ProcessPath와 대조한다. 경로가 다르거나 확인할 수 없으면 요청 프레임을 한 바이트도 쓰지 않고 오류 응답만 stdout으로 돌려주므로, 세션 쿠키가 담긴 postResult 페이로드가 선점 프로세스로 넘어가지 않는다.

7.3 등록

앱 시작 시 현재 EXE 경로를 host manifest에 기록하고 HKCU에 등록한다. 관리자 권한이 필요하지 않는다. 설정 RegisterEdge가 켜져 있으면 같은 manifest를 Edge 키(HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.daou.calendar_overlay)에도 등록하고, 꺼져 있으면 Edge 키만 삭제한다. Chrome/Edge 레지스트리 경로는 UninstallService.BuildNativeHostKeyPath에서 만들어 제거 경로(§22)와 같은 출처를 쓴다.

using System.IO;
using System.Text.Json;
using Microsoft.Win32;

namespace DaouCalendarOverlay.Services;

public sealed class NativeMessagingRegistrationService
{
    /// <summary>Chrome host 키(HKCU 상대 경로). 제거 경로(<see cref="UninstallService"/>)와 같은 출처에서 만든다.</summary>
    public static readonly string ChromeRegistryPath = UninstallService.BuildNativeHostKeyPath(UninstallService.ChromeBrowserKeyRoot);

    /// <summary>Edge host 키(HKCU 상대 경로). 제거 경로(<see cref="UninstallService"/>)와 같은 출처에서 만든다.</summary>
    public static readonly string EdgeRegistryPath = UninstallService.BuildNativeHostKeyPath(UninstallService.EdgeBrowserKeyRoot);

    private const string LogCategory = "nativehost.register";

    private static readonly JsonSerializerOptions JsonOptions = new(JsonSerializerDefaults.Web) { WriteIndented = true };

    public string ManifestPath { get; }

    public NativeMessagingRegistrationService()
    {
        var directory = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
            "DaouCalendarOverlay",
            "NativeMessaging");
        ManifestPath = Path.Combine(directory, NativeBridgeProtocol.HostName + ".json");
    }

    /// <summary>등록할 host 키 경로. Chrome이 항상 먼저이고, <paramref name="includeEdge"/>가 true면 Edge가 뒤따른다.</summary>
    public static IReadOnlyList<string> GetRegistryPaths(bool includeEdge) =>
        includeEdge
            ? new[] { ChromeRegistryPath, EdgeRegistryPath }
            : new[] { ChromeRegistryPath };

    /// <summary>Chrome과 Edge가 함께 쓰는 host manifest JSON.</summary>
    public static string BuildManifestJson(string executablePath)
    {
        var manifest = new
        {
            name = NativeBridgeProtocol.HostName,
            description = "Daou Calendar Overlay native messaging bridge",
            path = executablePath,
            type = "stdio",
            allowed_origins = new[] { NativeBridgeProtocol.ExtensionOrigin }
        };

        return JsonSerializer.Serialize(manifest, JsonOptions);
    }

    /// <summary>
    /// 현재 EXE 경로로 host manifest를 갱신하고 HKCU에 등록한다. Chrome 키 실패는 예외로 던지고,
    /// Edge 키 쓰기·삭제 실패는 경고 로그만 남긴다(Edge 미설치·정책 차단 환경에서도 기동을 막지 않는다).
    /// <paramref name="registerEdge"/>가 false면 Edge host 키만 제거한다.
    /// </summary>
    public void EnsureRegistered(bool registerEdge)
    {
        var executablePath = Environment.ProcessPath
            ?? throw new InvalidOperationException("현재 실행 파일 경로를 확인할 수 없습니다.");

        Directory.CreateDirectory(Path.GetDirectoryName(ManifestPath)!);
        File.WriteAllText(ManifestPath, BuildManifestJson(executablePath));

        foreach (var path in GetRegistryPaths(registerEdge))
        {
            if (string.Equals(path, ChromeRegistryPath, StringComparison.Ordinal))
            {
                using var chromeKey = Registry.CurrentUser.CreateSubKey(path, writable: true)
                    ?? throw new InvalidOperationException("Chrome Native Messaging 레지스트리 키를 만들 수 없습니다.");
                chromeKey.SetValue(null, ManifestPath, RegistryValueKind.String);
                continue;
            }

            try
            {
                using var edgeKey = Registry.CurrentUser.CreateSubKey(path, writable: true)
                    ?? throw new InvalidOperationException("Edge Native Messaging 레지스트리 키를 만들 수 없습니다.");
                edgeKey.SetValue(null, ManifestPath, RegistryValueKind.String);
            }
            catch (Exception ex)
            {
                LogService.Warn(LogCategory, "Edge Native Messaging 등록 실패", ex);
            }
        }

        if (!registerEdge)
            RemoveEdgeRegistration();
    }

    /// <summary>
    /// Edge host 키 하나만 지운다. 상위 NativeMessagingHosts 키와 Chrome 키는 지우지 않는다.
    /// 키가 없으면 아무것도 하지 않고, 실패는 경고 로그만 남긴다.
    /// </summary>
    private static void RemoveEdgeRegistration()
    {
        try
        {
            using (var existing = Registry.CurrentUser.OpenSubKey(EdgeRegistryPath))
            {
                if (existing is null)
                    return;
            }

            Registry.CurrentUser.DeleteSubKeyTree(EdgeRegistryPath, throwOnMissingSubKey: false);
            LogService.Info(LogCategory, "Edge Native Messaging 등록 해제");
        }
        catch (Exception ex)
        {
            LogService.Warn(LogCategory, "Edge Native Messaging 등록 해제 실패", ex);
        }
    }
}

9.3 실제 HTTP는 C#에서

Extension은 인증 정보만 제공하고 실제 API 요청은 C#에서 수행한다. 이를 통해 timeout, redirect 차단, HTML 로그인 페이지 감지, JSON code 검사, retry/backoff를 한 곳에서 처리한다.

        try
        {
            var requestUri = BuildCalendarUri(settingsSnapshot, fromSnapshot, toSnapshot);
            using var handler = HttpMessageHandlerFactory?.Invoke() ?? CreateDefaultHandler();
            using var client = new HttpClient(handler, disposeHandler: false)
            {
                Timeout = TimeSpan.FromSeconds(30)
            };
            using var request = new HttpRequestMessage(HttpMethod.Get, requestUri);
            request.Headers.TryAddWithoutValidation("Cookie", result.CookieHeader);
            request.Headers.TryAddWithoutValidation("Accept", "application/json, text/plain, */*");
            request.Headers.TryAddWithoutValidation("Accept-Language", "ko-KR,ko;q=0.9,en;q=0.8");
            if (!string.IsNullOrWhiteSpace(result.UserAgent))
                request.Headers.TryAddWithoutValidation("User-Agent", result.UserAgent);

            if (Uri.TryCreate(settingsSnapshot.BaseUrl, UriKind.Absolute, out var baseUri))
                request.Headers.Referrer = new Uri(baseUri, "/gw/app/calendar");

            using var response = await client.SendAsync(request, HttpCompletionOption.ResponseContentRead, cancellationToken);
            var body = await response.Content.ReadAsStringAsync(cancellationToken);
            var contentType = response.Content.Headers.ContentType?.MediaType ?? "";
            var location = response.Headers.Location?.ToString() ?? "";

            if (response.StatusCode is HttpStatusCode.Unauthorized or HttpStatusCode.Forbidden)
            {
                var retryAt = RecordFailure(authenticationFailure: true);
                SyncCompleted?.Invoke(this, BridgeSyncEventArgs.AuthRequired("Chrome의 DaouOffice 세션이 만료되었습니다.", retryAt));
                return;
            }

            if ((int)response.StatusCode is >= 300 and < 400)
            {
                var retryAt = RecordFailure(authenticationFailure: true);
                SyncCompleted?.Invoke(this, BridgeSyncEventArgs.AuthRequired("DaouOffice가 로그인 페이지로 리디렉션했습니다.", retryAt));
                return;
            }

            var looksLikeHtml = contentType.Contains("text/html", StringComparison.OrdinalIgnoreCase) ||
                                body.TrimStart().StartsWith("<", StringComparison.Ordinal);
            var redirectedToLogin = location.Contains("login", StringComparison.OrdinalIgnoreCase);

            if (looksLikeHtml || redirectedToLogin)
            {
                var retryAt = RecordFailure(authenticationFailure: true);
                SyncCompleted?.Invoke(this, BridgeSyncEventArgs.AuthRequired("Chrome의 DaouOffice 세션이 만료되었거나 로그인 페이지로 이동했습니다.", retryAt));
                return;
            }

            if (!response.IsSuccessStatusCode)
            {
                var retryAt = RecordFailure(authenticationFailure: false);
                SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Fail($"DaouOffice HTTP {(int)response.StatusCode}", BridgeFailureKind.Api, retryAt));
                return;
            }

            var envelope = JsonSerializer.Deserialize<DaouApiEnvelope>(body, _jsonOptions);
            if (envelope is null)
                throw new JsonException("응답 JSON이 비어 있습니다.");

            if (!IsSuccessCode(envelope.Code))
            {
                var message = string.IsNullOrWhiteSpace(envelope.Message) ? "DaouOffice API 오류" : envelope.Message!;
                var retryAt = RecordFailure(authenticationFailure: false);
                SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Fail(message, BridgeFailureKind.Api, retryAt));
                return;
            }

            if (DiscardIfRangeChanged(fromSnapshot, toSnapshot))
            {
                LogService.Warn("bridge", "표시 범위가 변경되어 이전 범위의 동기화 결과를 버리고 즉시 재발행합니다.");
                return;
            }

            RecordSuccess(settingsSnapshot.RefreshMinutes);
            SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Ok(envelope.Data, fromSnapshot, toSnapshot));
        }
        catch (HttpRequestException ex)
        {
            LogService.Warn("bridge.http", "DaouOffice 요청 네트워크 오류", ex);
            var retryAt = RecordFailure(authenticationFailure: false);
            SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Fail($"네트워크 오류: {ex.Message}", BridgeFailureKind.Network, retryAt));
        }
        catch (TaskCanceledException ex)
        {
            if (cancellationToken.IsCancellationRequested)
            {
                LogService.Info("bridge", "종료 중 HTTP 요청 취소");
                return;
            }

            LogService.Warn("bridge.http", "DaouOffice 요청 취소/시간 초과", ex);
            var retryAt = RecordFailure(authenticationFailure: false);
            var message = ex.InnerException is TimeoutException ? "DaouOffice 응답 시간 초과" : "네트워크 요청이 취소되었습니다.";
            SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Fail(message, BridgeFailureKind.Network, retryAt));
        }
        catch (Exception ex)
        {
            LogService.Warn("bridge.http", "DaouOffice 세션 브리지 실패", ex);
            var retryAt = RecordFailure(authenticationFailure: false);
            SyncCompleted?.Invoke(this, BridgeSyncEventArgs.Fail($"DaouOffice 세션 브리지 실패: {ex.Message}", BridgeFailureKind.General, retryAt));
        }

9.4 반복/음력

UI는 recurrence를 재계산하지 않는다. 조회 범위 내 occurrence가 API 결과의 개별 event로 내려오는 동작을 전제로 startTime/endTime을 그대로 표시한다. 음력 휴일도 서버 계산 결과를 신뢰한다.

같은 일정이 여러 캘린더에 공유되면 API는 동일한 id를 캘린더 수만큼 내려보낸다(실데이터 37건 중 5건). UI는 Models/EventDeduplicator.cs에서 id 기준으로 이를 1건으로 합치고, 소속 캘린더 ID/이름을 모두 CalendarIds/CalendarNames에 보존한다. 캐시 파일에는 병합 전 원본 이벤트를 그대로 저장하며(역호환), 병합은 캐시 로드 직후 화면에 표시하기 직전에 수행한다. 숨김 판정은 소속 캘린더가 모두 숨겨진 경우에만 적용되고, 하나라도 표시 중이면 일정은 계속 보인다.

10. 동기화 스케줄, 상태 머신, 재시도

10.1 두 개의 주기

Chrome 쪽

MV3 alarm: 30초. Worker를 깨워 native host에 getConfig를 물어본다. 알람이 계속 반복되므로 worker는 사실상 상시 활성이다.

앱 쪽

다음 fetch 시점을 정하는 것은 CalendarBridgeServer._nextAttemptAt이다(성공 시 설정의 RefreshMinutes, 실패 시 backoff). 앱에는 fetch를 유발하는 주기 타이머가 없다. 앱의 1초 시계 타이머는 시각 표시와 자정 전환 시 달력 재구성에만 쓴다.

30초마다 Daou API를 직접 때리는 구조가 아니다. worker는 getConfig 응답의 shouldFetch가 false면 그 회차를 fetch 없이 끝내고, 다음 알람에 다시 깨어난다.

확장이 syncOnce()를 호출하는 트리거는 5종이다. service worker 최초 로드 시의 top-level syncOnce() 호출은 제거됐고, 최상위에서는 ensureAlarm()만 수행한다(worker가 깨어날 때마다 host를 즉시 스폰하지 않는다).

  • chrome.runtime.onInstalled — 알람 보장 후 1회 동기화
  • chrome.runtime.onStartup — 알람 보장 후 1회 동기화
  • chrome.cookies.onChanged — 쿠키 도메인이 daouoffice.com 또는 그 서브도메인일 때, 5초 debounce(창 안의 연속 변경은 1회로 합침)
  • chrome.alarms.onAlarm — 기본 30초 주기 알람
  • chrome.action.onClicked — 툴바 아이콘 클릭

host 연결(getConfig sendNativeMessage)이 연속 3회 실패하면 확장 알람 주기가 1 → 2 → 5분으로 늘어나고, host가 다시 응답하면 30초로 복귀한다. 실패로 세는 것은 sendNativeMessage 자체가 예외를 던진 경우와, native host가 오버레이 파이프에 닿지 못해 ok: false로 답한 경우(오버레이 미실행 등)다. 실행 중인 오버레이는 getConfig에 항상 ok: true로 답하므로 이 응답이 오면 성공으로 보고 카운터를 0으로 되돌린다. ensureAlarm은 기존 알람의 periodInMinutes가 목표 주기와 다르면 chrome.alarms.create로 재생성한다. MV3 worker는 수시로 종료되므로 실패 카운터는 모듈 변수가 아니라 chrome.storage.session에 보관한다. postResult 전송 실패는 이 카운터에 반영하지 않는다.

10.2 중복 방지

fetch 발행 시 GUID requestId와 45초 lease를 만든다. postResult는 받은 requestId가 현재 활성 요청과 같은지만 확인하고 즉시 ok로 응답하며, 실제 DaouOffice HTTP 조회는 백그라운드 Task에서 수행한다. 결과를 받아들인 시점에 lease를 60초로 갱신하고 _activeRequestId는 그대로 두므로, 조회가 끝나기 전에는 새 fetch가 발행되지 않는다. lease와 _activeRequestId는 HTTP가 끝난 시점(성공·실패·취소 모두)에 그 사이 다른 요청으로 교체되지 않았을 때만 해제된다. 같은 requestId로 postResult가 두 번 들어와도 HTTP 조회는 한 번만 나간다. 파이프 서버 인스턴스는 4개이고 accept 루프가 요청 처리와 분리돼 있어, 조회가 오래 걸려도 getConfig/ping은 native host의 2.5초 connect timeout 안에 응답한다. shouldFetch가 false인 모든 응답에는 사유(noFetchReason: not_configured, invalid_base_url, range_not_ready, lease_active, backoff, not_due)가 함께 내려가고, 설정 문제(not_configured/invalid_base_url)는 상태 표시에 설정 오류: …로 노출된다. BaseUrl 정책은 Services/BaseUrlPolicy(https + *.daouoffice.com, apex 제외) 한 곳에서만 판정하며 확장 host_permissions(https://*.daouoffice.com/*)와 일치한다.

    private BridgeConfigResponse BuildConfig()
    {
        lock (_gate)
        {
            if (!_settings.IsConfigured)
                return BridgeConfigResponse.NoFetch(
                    BaseUrlPolicy.Validate(_settings.BaseUrl).IsValid
                        ? NoFetchReasons.NotConfigured
                        : NoFetchReasons.InvalidBaseUrl);

            if (_from == default || _to == default)
                return BridgeConfigResponse.NoFetch(NoFetchReasons.RangeNotReady);

            var validation = BaseUrlPolicy.Validate(_settings.BaseUrl);
            if (!validation.IsValid)
                return BridgeConfigResponse.NoFetch(NoFetchReasons.InvalidBaseUrl);

            var now = DateTimeOffset.Now;
            var leaseActive = !string.IsNullOrEmpty(_activeRequestId) && now < _leaseUntil;
            if (leaseActive)
                return BridgeConfigResponse.NoFetch(NoFetchReasons.LeaseActive);

            var due = _forceRefresh || _nextAttemptAt == default || now >= _nextAttemptAt;
            if (!due)
                return BridgeConfigResponse.NoFetch(_consecutiveFailures > 0 ? NoFetchReasons.Backoff : NoFetchReasons.NotDue);

            _activeRequestId = Guid.NewGuid().ToString("N");
            _leaseUntil = now.AddSeconds(45);
            _forceRefresh = false;

            return new BridgeConfigResponse
            {
                Ok = true,
                ShouldFetch = true,
                RequestId = _activeRequestId,
                BaseUrl = validation.NormalizedBaseUrl!,
                TimeMin = FormatDate(_from),
                TimeMax = FormatDate(_to),
                IncludingAttendees = true,
                CalendarIds = new List<string>(_settings.CalendarIds)
            };
        }
    }

    private NativeBridgeResponse AcceptResult(BridgeResultPayload result)
    {
        string requestId;
        AppSettings settingsSnapshot;
        DateTimeOffset fromSnapshot;
        DateTimeOffset toSnapshot;

        lock (_gate)
        {
            if (string.IsNullOrWhiteSpace(result.RequestId) ||
                !string.Equals(result.RequestId, _activeRequestId, StringComparison.Ordinal))
            {
                LogService.Warn("bridge", $"postResult 무시: requestId 불일치 (cookies={result.CookieCount}, source={result.CookieSource ?? "none"})");
                return NativeBridgeResponse.Success();
            }

            if (string.Equals(_processingRequestId, result.RequestId, StringComparison.Ordinal))
            {
                LogService.Warn("bridge", "postResult 무시: 같은 requestId가 이미 처리 중");
                return NativeBridgeResponse.Success();
            }

            requestId = _activeRequestId;
            _processingRequestId = requestId;
            settingsSnapshot = _settings.Clone();
            fromSnapshot = _from;
            toSnapshot = _to;
            _leaseUntil = DateTimeOffset.Now.AddSeconds(ResultLeaseSeconds);
        }

        var token = _cts.Token;
        var task = Task.Run(
            () => RunResultFetchAsync(result, requestId, settingsSnapshot, fromSnapshot, toSnapshot, token),
            CancellationToken.None);
        Track(task);

        return NativeBridgeResponse.Success();
    }

    private void ReleaseActiveRequest(string requestId)
    {
        lock (_gate)
        {
            if (string.Equals(_processingRequestId, requestId, StringComparison.Ordinal))
                _processingRequestId = "";

            if (!string.Equals(_activeRequestId, requestId, StringComparison.Ordinal))
                return;

            _activeRequestId = "";
            _leaseUntil = DateTimeOffset.MinValue;
        }
    }

10.3 backoff

인증 실패는 1분 뒤 재시도한다. 일반 네트워크/API 실패는 30초 → 60초 → 120초 → 240초 → 480초 수준으로 증가한다. 성공하면 실패 카운터를 초기화하고 refresh interval 기준으로 다음 due를 잡는다. 인증 실패도 _consecutiveFailures를 함께 증가시키며, 일반 실패 지연의 실제 상한은 480초다(코드에 적힌 600초 상한은 지수 계산상 도달하지 않는다).

    private void RecordSuccess(int refreshMinutes)
    {
        lock (_gate)
        {
            _consecutiveFailures = 0;
            _nextAttemptAt = DateTimeOffset.Now.AddMinutes(Math.Max(1, refreshMinutes));
        }
    }

    private DateTimeOffset RecordFailure(bool authenticationFailure)
    {
        lock (_gate)
        {
            _consecutiveFailures = Math.Min(_consecutiveFailures + 1, 8);
            var delay = authenticationFailure
                ? TimeSpan.FromMinutes(1)
                : TimeSpan.FromSeconds(Math.Min(600, 30 * Math.Pow(2, Math.Min(_consecutiveFailures - 1, 4))));
            _nextAttemptAt = DateTimeOffset.Now.Add(delay);
            return _nextAttemptAt;
        }
    }

    private static Uri BuildCalendarUri(AppSettings settings, DateTimeOffset from, DateTimeOffset to)
    {
        var baseUri = new Uri(settings.BaseUrl.TrimEnd('/') + "/", UriKind.Absolute);
        var endpoint = new Uri(baseUri, "gw/api/calendar/event");
        var query = new List<string>
        {
            $"timeMin={Uri.EscapeDataString(FormatDate(from))}",
            $"timeMax={Uri.EscapeDataString(FormatDate(to))}",
            "includingAttendees=true"
        };

        foreach (var calendarId in settings.CalendarIds)
            query.Add($"calendarIds%5B%5D={Uri.EscapeDataString(calendarId)}");

        var builder = new UriBuilder(endpoint)
        {
            Query = string.Join("&", query)
        };
        return builder.Uri;
    }

    private static bool IsSuccessCode(JsonElement code)
    {
        return code.ValueKind switch
        {
            JsonValueKind.String => string.Equals(code.GetString(), "200", StringComparison.Ordinal),
            JsonValueKind.Number => code.TryGetInt32(out var value) && value == 200,
            _ => false
        };
    }

    private static string FormatDate(DateTimeOffset value) =>
        value.ToString("yyyy-MM-dd'T'HH:mm:ss.fffzzz", CultureInfo.InvariantCulture);

확장 버전 불일치(T2.2): 7.1.0 worker의 getConfig 요청은 type, lastError, extensionVersion(chrome.runtime.getManifest().version), protocolVersion(1, NativeBridgeProtocol.ProtocolVersion과 같은 값)을 싣는다. 앱은 protocolVersion을 NativeBridgeRequest.ProtocolVersion(nullable)으로 받아 로그 요약(BridgeLogSummary.DescribeRequest의 protocolVersion=1)에만 남기고 협상에는 쓰지 않으며, 이 필드가 없는 구버전 확장(7.0.0)도 호환으로 처리한다. 앱은 getConfig 요청의 extensionVersion을 ChromeExtensionInstaller.ExpectedExtensionVersion(EXE에 임베드된 확장 버전)과 비교한다(Services/ExtensionVersionGuard, 순수 로직). 다르면 CalendarBridgeServer가 BridgeSyncEventArgs.ExtensionFailure(BridgeFailureKind.Extension)를 올리고 SyncStatusService.MarkExtensionVersionMismatch가 ExtensionError 상태로 “Chrome 확장 새로고침 필요 (보고 버전 → 기대 버전)”을 게시한다. 확장이 버전을 보고하지 않는 구버전이면 보고 버전 자리에 7.0.0 이하를 표시하며(7.0.0은 extensionVersion을 보내지 않은 마지막 버전이다), 확장이 30초마다 같은 조합을 보고해도 재발행은 억제된다. 현재 상태가 AuthenticationRequired이면 재로그인 안내가 더 급하므로 불일치를 게시하지 않고, 불일치 처리(App.BridgeServer_SyncCompleted의 BridgeFailureKind.Extension 분기)는 재로그인 배너(SetLoginRequired)를 건드리지 않는다. 불일치 신호는 SyncCompleted에 실려 오므로 fetch가 진행되는 동안에는 “동기화 중…”·“정상 · 동기화 HH:mm”과 불일치 문구가 번갈아 보일 수 있다. 확장을 새로고침해 버전이 일치하는 getConfig가 오면 CalendarBridgeServer.ExtensionVersionConfirmed → SyncStatusService.MarkExtensionVersionConfirmed로 “Chrome 브리지 연결됨 · 동기화 대기”로 해제된다(현재 상태가 ExtensionError일 때만, 다른 상태에서는 아무것도 게시하지 않는다). 동기화가 한 번 성공해 “정상”으로 바뀌어도 버전이 여전히 다르면 다음 getConfig에서 다시 표시된다. 불일치는 fetch를 막지 않는다(noFetchReason과 무관하며 동기화는 계속 진행된다).

public sealed class SyncStatusService
{
    private const string CacheOutOfRangeSuffix = " · 캐시(범위 밖)";

    /// <summary>
    /// 확장이 버전을 보고하지 않았을 때 보고 버전 자리에 쓰는 표기.
    /// 7.0.0은 getConfig에 extensionVersion을 보내지 않은 마지막 버전이다.
    /// </summary>
    private const string UnreportedExtensionVersionText = "7.0.0 이하";

    private readonly object _gate = new();
    private readonly Func<DateTimeOffset> _now;
    private DateTimeOffset _lastHeartbeat;
    private DateTimeOffset _lastSuccess;
    private bool _cacheOutOfRange;
    private DateTimeOffset _cachedAt;
    private OverlaySyncState _state = OverlaySyncState.Starting;
    private string _configurationInvalidReason = "";
    private string _extensionMismatchKey = "";

    public event EventHandler<SyncStatusChangedEventArgs>? StatusChanged;

    /// <param name="now">heartbeat 기록과 만료 판정에 쓰는 시계(테스트용). null이면 <see cref="DateTimeOffset.Now"/>.</param>

    public void MarkStarting() => Publish(OverlaySyncState.Starting, "시작 중…", false);

    public void MarkWaiting() => Publish(OverlaySyncState.WaitingForChrome, Decorate("Chrome 백그라운드 대기"), false);

    /// <summary>캐시가 오늘을 포함하지 않는 범위일 때 호출. 이후 대기/연결 대기 문구에 접미가 붙는다.</summary>
    public void MarkCacheOutOfRange()
    {
        lock (_gate)
            _cacheOutOfRange = true;
    }

    /// <summary>캐시를 읽어 화면에 표시했을 때 호출. 이후 대기/연결 대기 문구에 " · 캐시 MM-dd HH:mm"이 붙는다.</summary>
    public void MarkCacheLoaded(DateTimeOffset cachedAt)
    {
        if (cachedAt == default)
            return;

        OverlaySyncState state;
        lock (_gate)
        {
            _cachedAt = cachedAt;
            state = _state;
        }

        if (state == OverlaySyncState.WaitingForChrome)
            Publish(OverlaySyncState.WaitingForChrome, Decorate("Chrome 백그라운드 대기"), false);

            Publish(OverlaySyncState.Connected, Decorate("Chrome 브리지 연결됨 · 동기화 대기"), false);
    }

    {
        lock (_gate)
            _lastHeartbeat = _now();

        if (_state is OverlaySyncState.Starting or OverlaySyncState.WaitingForChrome)

    public void MarkSyncing() => Publish(OverlaySyncState.Syncing, "동기화 중…", false);

    public void MarkSuccess(DateTimeOffset when)
    {
        lock (_gate)
        {
            _lastSuccess = when;
            _cacheOutOfRange = false;
            _cachedAt = default;

        Publish(OverlaySyncState.AuthenticationRequired,

    public void MarkNetworkError(string? message, DateTimeOffset? retryAt = null)

    /// <summary>
    /// 확장 버전이 EXE가 기대하는 버전과 다를 때의 상태 문구를 만든다.
    /// 확장이 30초마다 같은 버전을 보고하므로 동일 조합의 재발행은 억제한다(MarkConfigurationInvalid와 같은 방식).
    /// 확장이 버전을 보고하지 않았으면(null·빈 값) 보고 버전 자리에 "7.0.0 이하"를 쓴다.
    /// 재로그인 안내가 더 급하므로 AuthenticationRequired 상태는 덮어쓰지 않는다(아무것도 게시하지 않는다).
    /// </summary>
    public void MarkExtensionVersionMismatch(string? reportedVersion, string expectedVersion)
    {
        var reported = string.IsNullOrWhiteSpace(reportedVersion) ? UnreportedExtensionVersionText : reportedVersion!.Trim();
        var expected = (expectedVersion ?? "").Trim();
        var key = reported + "→" + expected;
        lock (_gate)
        {
            if (_state == OverlaySyncState.AuthenticationRequired)
                return;
            if (_state == OverlaySyncState.ExtensionError &&
                string.Equals(_extensionMismatchKey, key, StringComparison.Ordinal))
                return;
            _extensionMismatchKey = key;
        }

        MarkExtensionError($"Chrome 확장 새로고침 필요 ({reported} → {expected})");
    }

    /// <summary>
    /// 확장 버전이 다시 일치함을 확인했을 때 호출한다. 현재 상태가 ExtensionError일 때만
    /// 연결됨 상태로 되돌리고, 그 외 상태에서는 아무것도 게시하지 않는다(30초마다 불리므로).
    /// </summary>

        OverlaySyncState state;

            state = _state;

            Publish(OverlaySyncState.Connected, Decorate("Chrome 브리지 연결됨 · 동기화 대기"), false);

    /// BaseUrl·캘린더 ID 등 설정 문제로 동기화가 불가능할 때의 상태.
    /// 확장이 30초마다 같은 사유를 다시 알려오므로 동일 사유의 재발행은 억제한다.
    /// </summary>

    /// <summary>설정·캐시 등 로컬 파일 저장이 실패했을 때의 상태 문구를 만든다.</summary>

    /// <summary>확장 추출·native host 등록처럼 기동 시 선택적 구성 요소가 실패했을 때. 오버레이는 계속 동작한다.</summary>
    /// <remarks>
    /// "{component} 실패: {reason} · 로그 확인"을 GeneralError로 게시하고, 이후 대기/연결 대기 문구 끝에
    /// " · {component} 실패" 접미를 붙인다. 같은 구성 요소는 접미에 한 번만 들어간다.
    /// </remarks>
    public void MarkStartupComponentError(string component, string reason)
    {
        if (string.IsNullOrWhiteSpace(component))
            return;

        var label = component + " 실패";
        lock (_gate)
        {
            if (!_startupIssues.Any(x => string.Equals(x, label, StringComparison.Ordinal)))
                _startupIssues.Add(label);

    private bool MatchesFilter(DaouCalendarEvent calendarEvent)
    {
        var needle = _filterText;
        if (string.IsNullOrWhiteSpace(needle))
            return true;

        return _filterField switch
        {
            "Owner" => Contains(calendarEvent.OwnerOrCreatorDisplay, needle) ||
                       Contains(calendarEvent.Creator?.Name, needle) ||
                       Contains(calendarEvent.Creator?.Email, needle),
            "Audience" => Contains(calendarEvent.AttendeeDisplay, needle) ||
                          calendarEvent.Attendees.Any(a => Contains(a.Name, needle) || Contains(a.Email, needle)),
            _ => Contains(calendarEvent.Summary, needle)
        };
    }

                    PipeName,

                    PipeOptions.Asynchronous);

                await client.ConnectAsync(350, CancellationToken.None);
                var payload = Encoding.UTF8.GetBytes("activate\n");
                await client.WriteAsync(payload);
                await client.FlushAsync();
                return;
            }
            catch
            {
                await Task.Delay(120);
            }
        }
    }

    private async Task ListenLoopAsync(CancellationToken cancellationToken)
    {
        while (!cancellationToken.IsCancellationRequested)
        {
            try
            {
                using var server = new NamedPipeServerStream(
                    PipeName,
                    PipeDirection.In,
                    maxNumberOfServerInstances: 1,
                    PipeTransmissionMode.Byte,
                    PipeOptions.Asynchronous | PipeOptions.CurrentUserOnly);

                await server.WaitForConnectionAsync(cancellationToken);
                using var reader = new StreamReader(server, Encoding.UTF8, detectEncodingFromByteOrderMarks: false, bufferSize: 1024, leaveOpen: true);
                var line = await reader.ReadLineAsync().WaitAsync(cancellationToken);
                if (string.Equals(line, "activate", StringComparison.OrdinalIgnoreCase))
                    ActivateRequested?.Invoke(this, EventArgs.Empty);
            }
            catch (OperationCanceledException)
            {
                break;
            }
            catch
            {
                if (!cancellationToken.IsCancellationRequested)
                    await Task.Delay(250, cancellationToken);
            }
        }
    }

    public async ValueTask DisposeAsync()
    {
        _cts.Cancel();
        if (_listenLoop is not null)
        {
            try { await _listenLoop; } catch { }
        }

        if (_ownsMutex && _mutex is not null)
        {
            try { _mutex.ReleaseMutex(); } catch { }
        }

        _mutex?.Dispose();
        _cts.Dispose();
    }
}

15. 보안·데이터 경계

적용된 보호

  • ID/PW를 앱에 저장하지 않음
  • Native Messaging allowed_origins를 고정 extension ID로 제한
  • Named Pipe CurrentUserOnly(서버·클라이언트 양쪽) + native host가 서버 프로세스 실행 파일 경로를 Environment.ProcessPath와 대조한 뒤에만 전송
  • API용 BaseUrl은 HTTPS + daouoffice.com/subdomain 검증
  • Cookie는 settings.json에 저장하지 않음
  • requestId + lease + HTTP 완료 후 표시 범위 재확인으로 stale result 무시
  • HTTP redirect 자동 추적 비활성화

주의할 데이터

  • calendar-cache.json에는 일정 제목/설명/참석자 등이 평문 JSON으로 남음
  • Cookie header는 동기화 순간 프로세스 메모리와 chrome.storage.session에 존재
  • Unpacked extension 폴더는 현재 Windows 사용자가 수정 가능
  • 내부 웹 API는 공식 public API 계약이 아님
Named Pipe 위협 모델: (1) 다른 로컬 계정의 프로세스가 같은 이름의 파이프를 먼저 만들어 선점하는 경로는 서버·클라이언트 양쪽 PipeOptions.CurrentUserOnly로 차단된다. (2) 동일 사용자 프로세스는 신뢰 경계 안이다. 같은 Windows 계정으로 실행되는 프로세스는 Chrome 프로필과 %LOCALAPPDATA%에 이미 접근할 수 있으므로, native host가 서버 실행 파일 경로를 Environment.ProcessPath와 대조하는 것은 심층 방어일 뿐이며 같은 EXE를 복제해 다시 실행하는 공격까지 막지는 못한다. (3) 싱글 인스턴스 활성화용 파이프(SingleInstanceService.NotifyPrimaryAsync)에는 activate 문자열만 흐르고 쿠키 등 비밀값이 없으므로 클라이언트 쪽에 CurrentUserOnly를 적용하지 않았다(적용하면 오버레이가 관리자 권한으로 실행됐을 때 활성화 신호가 깨진다).
향후 보안 강화 후보: 회사 정책이 엄격하면 Windows DPAPI로 calendar cache를 암호화하거나 cache disable 옵션을 추가하는 것이 가장 직접적이다.

버전 확인

EXE 버전과 Chrome 확장 버전은 같은 번호(현재 v7.1.0)를 쓰고, 네이티브 브리지 프로토콜은 NativeBridgeProtocol.ProtocolVersion(현재 1)으로 따로 관리한다. 확장은 같은 값을 getConfig 요청의 protocolVersion으로 실어 보내고, 앱은 이를 로그에만 남긴다(협상에 쓰지 않으며 필드가 없는 구버전 확장도 호환으로 처리). 실행 중인 버전은 트레이 아이콘 툴팁, 설정 창 하단, 로그 파일 첫 줄, EXE 속성 창(파일 버전 7.1.0.0)에서 확인할 수 있고 네 곳이 항상 같아야 한다. 로그 첫 줄과 EXE 속성 창의 제품 버전에는 빌드 커밋 SHA가 붙은 7.1.0+<커밋 SHA>가 보인다(git 저장소에서 빌드한 경우 SDK가 자동으로 붙인다). 다르면 EXE 교체 후 오버레이를 재시작하지 않았거나 chrome://extensions에서 확장을 새로고침하지 않은 것이다.

19. 알려진 한계와 유지보수 포인트

  1. Daou 내부 API 의존: endpoint/query/JSON field 변경 시 bridge/model 수정 필요.
  2. Chrome 의존: Chrome process가 완전 종료되면 새로운 sync는 불가능하고 캐시만 표시.
  3. 세션 만료: 서버 absolute lifetime 만료 시 Chrome 재로그인 필요.
  4. Unpacked extension: 현재 개발자 모드 수동 설치. 다수 배포 시 enterprise policy/정식 패키징 고려.
  5. KST 가정: 날짜 판정에 +09:00이 명시됨.
  6. 로컬 캐시 평문: 보안정책에 따라 DPAPI 암호화 후보.
  7. .NET 8 지원 종료(2026-11-10): 현재 TFM은 net8.0-windows이며 .NET 10 이전 시험 결과는 docs/net10-migration.md에 기록. 전환은 별도 릴리스로 결정.

21. 성능 특성 (native host 스폰 비용)

확장은 chrome.runtime.sendNativeMessage(sendNative)로 host를 호출하고, Chrome은 호출마다 host 프로세스를 새로 띄운다(연결을 유지하지 않는다). 30초 알람마다 getConfig로 1회, 앱이 가져올 때라고 답한 회차에는 postResult가 더해져 2회 스폰된다. 30초 주기면 하루 2,880회 이상이므로 스폰당 기동·종료 비용이 곧 백그라운드 상시 비용이다. 오버레이가 실행 중이 아니면 host는 파이프 연결을 최대 2,500 ms 기다린 뒤 실패하므로(§20) 그 경우의 스폰당 경과 시간은 아래 표보다 길다.

측정 방법

  • 스크립트: tools/Measure-HostSpawn.ps1 -ExePath <EXE 경로> -Label <이름> -Iterations 20
  • Chrome과 같은 인자(chrome-extension://gkchgbpcbljkgabjcgjelacfkphcmhmi/ --parent-window=0)와 stdin/stdout/stderr 리디렉션으로 EXE를 띄운 직후 stdin을 닫는다. host는 빈 입력(EOF)을 받아 파이프에 연결하지 않고 정상 종료하므로, 측정값은 파이프 왕복·HTTP 시간을 뺀 프로세스 시작~종료 비용이다.
  • 경과 시간은 Process.Start 직전부터 WaitForExit 반환까지(Stopwatch), CPU 시간은 종료된 프로세스의 TotalProcessorTime이다. CPU 시간은 모든 스레드의 합이고 Windows 스케줄러 틱(15.625 ms) 단위로 기록되므로 경과 시간보다 클 수 있다.
  • 첫 회차는 워밍업으로 버리고 이후 20회를 표본으로 쓴다.

22. 설치 · 업그레이드 · 제거

배포 단위는 EXE 하나이고 별도 설치 프로그램은 없다. Native Messaging Host 등록(HKCU 키 + manifest)은 앱이 기동할 때마다 스스로 다시 만들고, HKCU Run 값은 설정의 Windows 시작 시 실행 옵션에 따라 기동 시 만들거나 지운다. 등록 해제는 아래 제거 경로로만 한다. 설정·캐시·로그·추출된 확장은 모두 %LOCALAPPDATA%\DaouCalendarOverlay에 있어 EXE를 교체해도 유지된다.

설치

  1. DaouCalendarOverlay.exe를 둘 폴더에 복사해 실행한다. 기동 시 확장 파일을 %LOCALAPPDATA%\DaouCalendarOverlay\ChromeExtension에 추출하고, Native Messaging manifest(%LOCALAPPDATA%\DaouCalendarOverlay\NativeMessaging\com.daou.calendar_overlay.json)의 path를 현재 실행 중인 EXE 경로로 다시 기록한 뒤 HKCU에 host를 등록한다.
  2. 최초 실행이면 설정창에서 DaouOffice 주소(https://회사이름.daouoffice.com)와 캘린더 ID를 입력한다.
  3. chrome://extensions에서 개발자 모드를 켜고 위 ChromeExtension 폴더를 압축해제된 확장으로 로드한다(트레이 “Chrome 확장 폴더 열기”로 폴더를 바로 열 수 있다).

업그레이드

  1. 트레이 우클릭 → 종료로 앱을 끈다.
  2. EXE 파일을 새 버전으로 교체한다.
  3. 새 EXE를 실행한다. 확장 파일이 새 버전으로 다시 추출되고 manifest의 path가 새 EXE 경로로 갱신된다.
  4. chrome://extensions에서 확장을 새로고침한다. 새로고침하지 않으면 이전 Service Worker가 계속 동작하고, 확장 버전이 바뀐 업그레이드라면 상태 표시줄에 “Chrome 확장 새로고침 필요 (x → y)”가 표시된다(§18).
파일 잠금: 오버레이가 실행 중이면 EXE 파일이 잠겨 있어 교체가 실패한다. 반드시 1단계에서 앱을 종료한 뒤 교체한다. Chrome이 같은 EXE를 host로 띄운 동안(오버레이가 꺼져 있으면 파이프 대기 최대 2,500 ms)에도 파일이 잠기므로, 교체가 실패하면 잠시 뒤 다시 시도한다.

제거

진입점은 두 가지이며 둘 다 UninstallFlow.Confirm()의 확인 창 2단계(등록 해제 확인 → 사용자 데이터 폴더 삭제 여부)를 거친다. 어느 단계에서든 취소하면 아무것도 바꾸지 않는다.

  • 트레이 “완전 제거…” — UninstallService.Run(removeUserData: false)로 레지스트리 등록만 먼저 해제하고 결과 창을 보인 뒤 앱을 종료한다. 사용자 데이터 삭제를 선택했으면 실행 중인 프로세스가 파일을 다시 쓰지 않도록 ExitApplicationAsync의 마지막 단계(창을 닫은 뒤, Shutdown() 직전)에서 UninstallService.TryRemoveUserData로 폴더를 지운다.
  • 명령줄 DaouCalendarOverlay.exe --uninstall(/uninstall, -uninstall도 인식, 대소문자 무관) — Program.Main이 StartupModeParser.IsUninstallInvocation을 IsNativeInvocation 분기보다 먼저 판정하므로 WPF App을 만들지 않고 UninstallFlow.RunInteractive()만 실행한다. 로그는 overlay 접두 파일에 남고, 종료 코드는 실패 항목이 있으면 1, 그 밖에는(취소 포함) 0이다. 실행 중인 오버레이는 설정 저장 때 등록을 다시 만들므로 먼저 트레이에서 종료한 뒤 실행한다.

레지스트리 항목은 하나씩 따로 처리해 하나가 실패해도 나머지를 계속 지우고, 처음부터 없던 항목은 건너뛴다. 결과 창에는 실제로 지운 항목과 실패한 항목만 나온다. 사용자 데이터 폴더는 절대 경로이고 드라이브 루트가 아니며 폴더 이름이 DaouCalendarOverlay일 때만 지운다.

레지스트리 대상 목록은 UninstallService.GetRegistryTargets() 한 곳에서 만들고, host 이름은 문자열로 적지 않고 NativeBridgeProtocol.HostName을 참조한다.

    /// <summary>
    /// 브라우저 레지스트리 루트(예: <c>Software\Google\Chrome</c>)에서 Native Messaging Host 키 경로를 만든다.
    /// </summary>
    public static string BuildNativeHostKeyPath(string browserKeyRoot)
    {
        if (string.IsNullOrWhiteSpace(browserKeyRoot))
            throw new ArgumentException("브라우저 레지스트리 루트가 비어 있습니다.", nameof(browserKeyRoot));

        var root = browserKeyRoot.Trim('\\');
        if (string.IsNullOrWhiteSpace(root))
            throw new ArgumentException("브라우저 레지스트리 루트가 비어 있습니다.", nameof(browserKeyRoot));

        return $@"{root}\NativeMessagingHosts\{NativeBridgeProtocol.HostName}";
    }

    /// <summary>제거할 레지스트리 항목 3개(Run 값, Chrome host 키, Edge host 키)를 이 순서로 돌려준다.</summary>
    public static IReadOnlyList<UninstallTarget> GetRegistryTargets() => new[]
    {
        new UninstallTarget(RunKeyPath, RunValueName, "시작 프로그램 등록(HKCU Run)"),
        new UninstallTarget(BuildNativeHostKeyPath(ChromeBrowserKeyRoot), null, "Chrome Native Messaging Host 등록"),
        new UninstallTarget(BuildNativeHostKeyPath(EdgeBrowserKeyRoot), null, "Edge Native Messaging Host 등록")
    };

제거 후 남는 것

  • Chrome/Edge 확장 — 앱이 지우지 않는다. chrome://extensions(Edge는 edge://extensions)에서 직접 제거한다.
  • EXE 파일 — 앱이 지우지 않는다. 제거가 끝난 뒤 수동으로 삭제한다. 제거 후 EXE를 다시 실행하면 기동 시 등록이 다시 만들어진다.
순서 주의: 등록을 해제하지 않고 EXE만 지우면 HKCU의 Native Messaging Host 등록이 남아 Chrome이 존재하지 않는 경로의 EXE를 계속 실행하려 하고, HKCU Run 값도 남아 Windows 로그인 때마다 없는 파일을 실행하려 한다. EXE를 지우기 전에 반드시 위 제거 경로를 먼저 실행한다.

24. 빌드 전제조건·릴리스 절차

개발 빌드와 릴리스 publish는 설정이 나뉘어 있다. 개발 빌드는 csproj만 읽어 framework-dependent로 만들고, 릴리스는 publish.ps1이 publish 프로파일 win-x64(16.3)로 self-contained 단일 EXE를 만든다.

24.1 전제조건

항목요구 사항

.NET SDK8.0 이상(현재 개발 머신은 SDK 10.x). TFM은 net8.0-windows

개발 빌드 실행.NET 8 데스크톱 런타임(Microsoft.WindowsDesktop.App 8.x, .NET 8 SDK에 포함). 개발 빌드는 framework-dependent라 런타임이 PC에 설치돼 있어야 한다. 릴리스 EXE는 런타임을 포함하므로 필요 없다

24.2 개발 빌드

dotnet build DaouCalendarOverlay.sln -c Release
dotnet test DaouCalendarOverlay.sln -c Release

출력은 DaouCalendarOverlay\bin\Release\net8.0-windows\이고 framework-dependent다. coreclr.dll 같은 .NET Runtime 파일이 출력에 복사되지 않는다. PDB는 portable 형식(DaouCalendarOverlay.pdb)으로 EXE 옆에 함께 나온다. 이 출력은 개발·테스트용이며 배포하지 않는다.

24.3 릴리스

.\publish.ps1 -DryRun
.\publish.ps1
.\publish.ps1 -Version 7.1.0 -OutputDir C:\release\DaouCalendarOverlay
.\publish.ps1 -CertificateThumbprint <인증서 SHA1 지문>

실행 정책 때문에 막히면 powershell -ExecutionPolicy Bypass -File .\publish.ps1로 실행한다.

파라미터기본값의미
-Version(생략)생략하면 csproj <Version>을 쓴다. 주면 csproj <Version>과 같아야 하며, 다르면 “Version mismatch”로 중단된다. 버전을 바꾸는 수단이 아니라 릴리스 담당자가 의도한 버전인지 확인하는 가드다. 형식이 x.y.z 또는 x.y.z.w가 아니면 “Invalid version”으로 중단된다
-OutputDir저장소 루트의 publishpublish 출력 폴더. 실행할 때마다 먼저 지우고 다시 만든다
-CertificateThumbprint(비어 있음)주면 signtool sign /sha1 <지문> /fd SHA256 /tr <TimestampUrl> /td SHA256으로 최종 EXE를 서명한다. 비어 있으면 서명을 건너뛴다
-TimestampUrlhttp://timestamp.digicert.com서명 시 사용할 RFC 3161 타임스탬프 서버
-DryRun꺼짐빌드도 파일 변경도 하지 않고 계획(VERSION, PROJECT, PUBLISH_DIR, SYMBOLS_DIR, ARTIFACT, PROFILE, SIGN, DRYRUN)만 출력한 뒤 종료 코드 0으로 끝난다. 위 버전 검증은 DryRun에서도 먼저 수행된다
산출물설명
publish\DaouCalendarOverlay-<버전>.exe배포할 self-contained 단일 EXE(현재 DaouCalendarOverlay-7.1.0.exe)
publish\symbols\*.pdb크래시 분석용 portable PDB. 배포하지 않고 같은 버전의 EXE와 짝지어 보관한다

모든 dotnet/signtool 호출은 Invoke-Checked를 거쳐 $LASTEXITCODE가 0이 아니면 예외를 던진다. 따라서 restore·publish·서명 중 어느 단계에서 실패해도 스크립트는 비정상 종료 코드로 끝나고 “Publish completed”는 출력되지 않는다(이전 스크립트는 네이티브 명령이 실패해도 “Publish completed”를 출력했다).

  1. 버전을 확인한다. 올리는 릴리스라면 아래 주의대로 csproj와 app.manifest를 먼저 고치고 CHANGELOG.md에 절을 추가한다.
  2. dotnet build DaouCalendarOverlay.sln -c Release(경고 0)와 dotnet test DaouCalendarOverlay.sln -c Release(실패 0)를 확인한다.
  3. .\publish.ps1 -Version <버전> -DryRun으로 ARTIFACT= 줄의 산출물명을 확인한다.
  4. .\publish.ps1 -Version <버전>(인증서가 있으면 -CertificateThumbprint 추가)로 publish한다.
  5. publish\DaouCalendarOverlay-<버전>.exe를 배포하고 publish\symbols\의 PDB는 따로 보관한다. 사용자 PC의 설치·업그레이드는 §22 절차를 따른다.
버전 올리기: -Version으로는 버전을 바꿀 수 없다. 버전을 올리려면 csproj의 Version/AssemblyVersion/FileVersion과 app.manifest의 assemblyIdentity version을 먼저 함께 고친다. 커맨드라인으로 버전 속성만 덮어쓰면 트레이·설정창·로그에 보이는 버전(InformationalVersion)과 EXE 속성 창의 파일 버전이 어긋난다. EXE와 Chrome 확장은 같은 버전 번호를 쓰므로(§18 버전 확인) ChromeExtension/manifest.json과 ChromeExtensionInstaller.ExpectedExtensionVersion도 같은 번호로 맞추며, 테스트가 이 일치를 확인한다.

24.4 코드 서명

현재 코드 서명 인증서를 확보하지 않아 릴리스 EXE는 미서명이다. 인터넷이나 메신저로 받은 미서명 EXE는 처음 실행할 때 Windows SmartScreen 경고가 뜰 수 있다. 인증서를 확보하면 인증서 저장소에 설치한 뒤 -CertificateThumbprint <SHA1 지문>으로 publish한다. 스크립트가 signtool로 최종 EXE(DaouCalendarOverlay-<버전>.exe)를 서명하고 -TimestampUrl의 서버로 타임스탬프를 붙인다. signtool을 찾지 못하거나 서명이 실패하면 스크립트는 비정상 종료 코드로 중단된다.
